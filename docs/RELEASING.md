# עדכוני גרסה

כל שינוי שממוזג ל-`main` עולה אוטומטית (Vercel). משתמשים עם האפליקציה פתוחה רואים פס "גרסה חדשה זמינה" (בדיקה כל 5 דקות וכשחוזרים לאפליקציה), ואחרי העדכון נפתח להם "מה חדש".

## איך משחררים גרסה

1. מעלים את מספר הגרסה ב-`package.json`:
   - תיקון קטן: `npm version patch --no-git-tag-version` (1.0.0 → 1.0.1)
   - פיצ'ר חדש: `npm version minor --no-git-tag-version` (1.0.0 → 1.1.0)
2. מוסיפים רשומה **בראש** `src/lib/changelog.ts`:
   ```ts
   { version: "1.1.0", date: "2026-12-01", title: "טיימר בליינדים", items: ["טיימר לטורנירים", "..."] },
   ```
3. מיזוג ל-`main`. זהו.

## מה המשתמש רואה

- **פס עדכון** בראש המסך כשיש build חדש. לחיצה מרעננת לגרסה החדשה.
- **"מה חדש"** נפתח פעם אחת אחרי עדכון, עם כל הגרסאות שפספס.
- **מספר גרסה** בתחתית מסך "השולחנות שלי". לחיצה פותחת את כל ההיסטוריה.

## שינויים במסד הנתונים

קובץ חדש לכל שינוי: `supabase/migrations/<YYYYMMDDHHMMSS>_<name>.sql` (מספר גרסה ייחודי). אין צורך להריץ ידנית: `scripts/migrate.mjs` רץ בתחילת כל build של production ב-Vercel ומחיל את מה שחסר (נרשם ב-`app_meta.migrations`). אם מיגרציה נכשלת, ה-build נכשל והגרסה הקודמת ממשיכה לרוץ. לפני כן ה-CI מריץ את כל המיגרציות על מסד נקי ואת בדיקות `supabase/tests`. שינויים צריכים להיות תואמים לאחור (להוסיף עמודות, לא למחוק), כי בזמן ההעלאה יש עדיין משתמשים על הגרסה הקודמת.

## אפליקציית אנדרואיד

ה-APK הוא מעטפת (TWA) שטוענת את האתר, אז **פיצ'רים חדשים לא דורשים APK חדש**. בונים APK חדש רק אם משנים שם, אייקון או הרשאות.
